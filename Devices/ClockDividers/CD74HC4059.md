# CD74HC4059

GPIO driver for the programmable counter, independent of the DDC114 driver.
Supports all five first-section modes and their specified design ranges:
N=3..15999 for /2, /4, /8 and N=3..9999 for /5, /10. Extended binary-decade
ranges are deliberately excluded. The default /8 mode covers the full range
and leaves master preset by changing only Kc.

`Encode` is a pure function returning the J1..J16 bit pattern and Ka/Kb/Kc.
It divides N by the selected mode, encodes three decimal quotient digits into
J5..J16, and combines the remainder and quotient thousands in J1..J4.
For TI's N=8479, /5 example, it produces jam word 0x695C.

`Configure` enters master preset, waits, drives LE low and programs all inputs,
waits again, then selects the counting mode. The supplied callback must wait
at least four CP periods on each call with CP running. This conservatively
covers TI's requirement for three complete pulses at an arbitrary entry phase.
The callback and all GPIOs are required; invalid configuration changes nothing.
Calls must be serialized and the callback must not throw.

```cpp
#include "CD74HC4059.h"
#include "Delay.h"
using LowLevelEmbedded::Devices::ClockDividers::CD74HC4059;

// Utility::Delay_us must already have been assigned by the application.
CD74HC4059 divider(
    {&j1, &j2, &j3, &j4, &j5, &j6, &j7, &j8,
     &j9, &j10, &j11, &j12, &j13, &j14, &j15, &j16},
    ka, kb, kc, le,
    [](uint32_t periods) {
        // Board CP is 4 MHz. One microsecond per requested period is a
        // conservative delay (four times the nominal minimum).
        LowLevelEmbedded::Utility::Delay_us(periods);
    });

// Stop downstream acquisition before changing divider configuration.
if (!divider.Configure(4000))
{
    // Invalid divisor, missing GPIO, or missing wait callback.
}
// Q now repeats nominally every 1 ms at 4 MHz, but is HIGH for only 250 ns.
```

`HoldInPreset` suspends counting; an already imminent output pulse can still
occur. It is not a guaranteed output-low clamp. `SetLatchEnabled(true)` holds
Q high after the next pulse; clearing LE releases it. Latching does not create
a free-running square wave. GPIO changes are sequential, so reconfiguration
is not glitch-free. Respect the chip's CP setup times; arrange external clock
control/synchronization if a deterministic restart phase is required. The first
count after master preset has an extra clock cycle per the datasheet.

## Connection to DDC114 in the supplied schematic

J1..J5 are PA0..PA4; J6..J8 are PB1, PB2, PB4; J9..J16 are PB8..PB15.
Ka/Kb/Kc are PA8/PA9/PA10, and LE is PA7. Verify GPIO/debug routing for PB4.
CP is the 4 MHz oscillator and Q connects directly to DDC114 CONV.

**Q is a pulse train, not a square wave.** With LE low, its 250 ns high time
at 4 MHz does not provide the DDC114's intended continuous integration interval
on both sides. Changing N changes pulse spacing, not pulse width. The DDC114
also requires a >=50 us first CONV pulse at startup. Do not equate `Configure(4000)`
with a working 1 ms DDC114 integration setting. Choose and verify a suitable
CONV waveform (for example, pulse-to-toggle hardware for continuous operation,
or a separately designed timed LE sequence) before using the acquisition path.
No automatic LE sequencing or pulse-to-square-wave conversion is implemented.
