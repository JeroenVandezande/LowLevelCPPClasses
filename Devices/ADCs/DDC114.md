# DDC114

Portable single-device driver using `ISPIAccess` and `IOPIN`. Includes all four
channels, 16-bit/20-bit readout, GPIO range/format selection, and rejection of the
first four retrieved conversions after initialization. It returns native ADC
codes; it does not implement the voltage-oriented `IADC` interface.

## Wiring and SPI

- DCLK -> SPI SCK; DOUT -> SPI MISO. No command bytes or MOSI connection required.
- Use **Mode0, MSB first, 8-bit transfers**, DCLK idle low, at most 16 MHz.
  The first bit is present before clocking; falling edges advance the output.
- There is **no CS pin**. Use a dedicated SPI clock (or external clock gating).
  Do not share an ungated SCK with other devices. The adapter's `csID` must select
  a route with no physical CS. The STM32 adapter supports construction without CS.
- DVALID -> GPIO input (active low), optionally with a falling-edge interrupt.
- RANGE0/1/2, FORMAT and TEST -> GPIO outputs, or fixed external levels.
  Null control-pin pointers mean externally controlled pins; the arguments to
  `Initialize` must match those levels. TEST must be low for normal measurement.
- CLK and CONV are supplied externally. The driver neither generates CONV nor
  programs a clock divider. HISPD/LOPWR and CLK_4X are also board configuration.
- For a single device, tie unused DIN and complementary DIN/DCLK inputs to DGND;
  leave unused complementary DOUT unconnected.

## Supplied schematic

The ADC sheet uses a 4 MHz oscillator for CLK and a CD74HC4059 for CONV.
CLK_4X and HISPD/LOPWR are low, selecting low-power operation. RESET is connected
to `nMCU_Reset`, so the driver deliberately does not pulse it.

The MCU sheet routes DCLK/DOUT to SPI1 PA5/PA6, RANGE0/1/2 to PC10/PC11/PC12,
DVALID to PC13, FORMAT to PB0, and TEST to PA15. Configure PA15 for GPIO rather
than JTAG as appropriate for the MCU's debug setup. CD74HC4059 configuration
belongs in the application, using the separate
[CD74HC4059 driver](../ClockDividers/CD74HC4059.md).
Its normal output is only one oscillator cycle wide (250 ns here), not a
square wave. Programming N alone does not provide suitable continuous-mode
CONV timing; see that driver's waveform discussion before acquisition.

## Example

```cpp
#include "DDC114.h"
using LowLevelEmbedded::Devices::ADCs::DDC114;

// spi1 implements ISPIAccess without a CS pin; the other objects implement IOPIN.
DDC114 adc(spi1, dvalid, {&range0, &range1, &range2, &format, &test});

// Board startup/reset sequencing is complete and CONV is stopped here.
if (!adc.Initialize(DDC114::Range::PicoCoulombs250, DDC114::Format::Bits20))
{
    // Invalid configuration.
}
// Configure/enable the CD74HC4059 in board code, then service each DVALID event.
DDC114::Samples sample;
// Call inside a scheduled safe read window (see below).
if (adc.TryRead(sample) == DDC114::ReadResult::Ready)
{
    const uint32_t ain1 = sample.channels[0];
    // Process ain1; channels[1..3] are AIN2..AIN4.
}
```

`TryRead` does not wait for DVALID. Once ready, it performs one synchronous
10-byte (20-bit) or 8-byte (16-bit) transfer. `Settling` means a complete frame
was consumed but discarded; `NotReady` performs no transfer. The output is
unchanged for every result other than `Ready`. Service the first four events
normally to drain startup data. Calling `Initialize` again restarts that count.

## Timing and startup responsibilities

Supply/reset/oscillator/divider sequencing belongs to the application and board:
TI specifies holding RESET low until at least 10 ms after supplies settle,
waiting 50 us after release before starting CLK/CONV, and a first CONV pulse
of at least 50 us. A standalone reset pulse must be at least 50 us. Follow the
power-up timing even though RESET is shared with the MCU; software running after
reset cannot by itself sequence an already running oscillator/divider.

In low-power continuous operation at 4 MHz, each CONV integration interval must
be at least 400 us; in high-speed operation at 4.8 MHz, at least 320 us. These are
intervals between CONV transitions, not automatically its full period. Ensure
the divider waveform satisfies the desired mode; short pulses can select
non-continuous operation, whose timing differs.

Keep DCLK inactive for at least 10 us on **both sides of every CONV transition**.
DVALID alone does not enforce this: a late poll can start too close to the next
edge. Schedule the read promptly after DVALID with a known divider phase and
sufficient room for the full transfer, including interrupt and SPI setup latency.
Finish before the next conversion replaces the data. The driver cannot detect
missed conversions or attach a reliable A/B integrator identity without external
timing information. Do not change range/format while acquisition is running.

`ISPIAccess` returns no transport status. Check the concrete adapter's status
(e.g. STM32 `LastStatus()`) after a read; `Ready` only describes the driver's
readout flow. After a failed/partial transfer, re-establish frame alignment with
a fresh conversion and reinitialize after a device reset if necessary.

## Interpreting codes

Wire order is AIN4 through AIN1; the driver reverses it for the public array.
20-bit codes are packed without padding (two channels occupy five bytes).
16-bit mode truncates the lowest four bits. Codes are unsigned offset binary:
nominal zero input is 4096 in 20-bit mode or 256 in 16-bit mode. Saturation is
0 or 0xFFFFF/0xFFFF. Do not interpret these values as signed two's complement
or assume code zero means zero current. Converting to current requires the
actual range, integration time, reference voltage and offset/gain calibration;
physical-quantity APIs added by an application should use UnitsNet types.

Reference: [TI DDC114 datasheet, SBAS255C](https://www.ti.com/lit/ds/symlink/ddc114.pdf),
especially pages 13, 21 and 26. Board mapping: supplied `Untitled.pdf`, sheets 3 and 8.

## Host tests

```sh
cmake -S tests -B /tmp/lowlevel-ddc114-tests
cmake --build /tmp/lowlevel-ddc114-tests
ctest --test-dir /tmp/lowlevel-ddc114-tests --output-on-failure
```

Tests cover SPI transaction shape, channel order and nibble boundaries, both
formats, all range-pin combinations, ready polarity, startup discard, and invalid
configuration. Hardware timing still requires verification on the target board.
